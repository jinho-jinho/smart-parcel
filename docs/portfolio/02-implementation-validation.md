# 구현 검증 기록

검증일: 2026-09-24. 이 문서가 포함된 커밋의 기능 범위를 기준으로 한다.

## 실행 환경

- Java 17, Gradle wrapper 8.14.3, Spring Boot 3.5.4
- 로컬 PostgreSQL 17.5의 전용 테스트 인스턴스/DB
- Python 3 표준 라이브러리
- 사용자 운영 DB에는 마이그레이션을 실행하지 않았다.

## 결과

| 검사 | 결과 |
| --- | --- |
| Java/Spring 테스트 | 12개 통과, 실패·오류·건너뜀 0 |
| Python 시뮬레이터 테스트 | 3개 통과 |
| Docker Compose 구성 검증 | 통과 (구문/환경 해석 검사, 컨테이너 실행 시험은 아님) |
| Git diff 공백 검사 | 통과 |

Java 검증에는 벨트 A/B 설정 독립성, 타 조직·장비·슈트 연결 거절, 이전 버전 결과 수신,
배포 후 설정 수정 거절, 배포/편집 경쟁, 이미지 접근 권한, 트랜잭션 롤백,
배출 성공/실패 도착 순서, 직원 권한과 조직 가입 경계를 포함한다.
같은 판정 24회 재전송을 작업자 8개로 실행해 시도·이벤트·이미지가 한 번만 저장되는지 확인했다.
같은 오류 재전송에서 사용자별 알림 중복이 없는지도 검증했다.

기존 스키마/사용자/설정/이력이 있는 별도 DB를 생성하고 명시적 Flyway baseline 후 V2/V3을 적용했다.
기존 이력을 보존하고 모호한 N:M 목적지를 migration_issues로 기록하며,
과거 장비와 이벤트를 추측해 생성하지 않는지 확인했다.

Python 데모 생성기는 사용자 JWT로 실제 HTTP 관리 API를 호출해 두 벨트를 생성했다.
시뮬레이터는 해당 HTTP 서버에 설정 조회/적용 보고, PNG 판정과 오류를 전송하고 같은 ID를 재전송했다.
Python 단위 테스트는 SQLite 재시작 후 본문·ID·이미지 보존, 서버 커밋 후 응답 유실 모형,
409 충돌 기록 보존을 확인했다. 실제 네트워크를 10분 끊은 시험은 아직 수행하지 않았다.

## 제한과 후속 측정

- 100벨트 부하, p95/p99, 처리량 개선율, 10분 단절 뒤 복구 시간은 아직 측정하지 않았다.
- 실제 AI/Arduino 하드웨어와 기존 React/Flutter의 새 API 연동은 이번 검증에 포함하지 않았다.
- 이미지 BYTEA의 대량 저장 비용과 보관/용량 정책은 후속 검증 대상이다.
- 재현 명령과 API 계약은 [실행 문서](../multi-belt.md), 설계 부하는 [요구사항](01-expansion-requirements.md)을 따른다.
